# B737-CLASSIC-CDU — FCOM §11.40.6–11.40.9: INIT/REF INDEX and IDENT

**منبع:** تصاویر کاربر از Boeing 737 Classic FCOM، بخش FMC Preflight، صفحات نمایشگر PDF **1558–1561** و شماره‌های چاپی **11.40.6–11.40.9** (ویرایش **15 دسامبر 2022**). صفحهٔ چاپی **11.40.5** در این دسته ارسال نشده است. هش SHA-256 هر تصویر در فایل JSON نگهداری شده است؛ تصاویر دارای حق نشر بوئینگ وارد مخزن عمومی نشده‌اند.

## 11.40.6 — نقشهٔ INIT/REF INDEX، نمایش 1/1

این تصویر برخلاف معرفی کلیِ صفحهٔ قبلی، **LSKهای واقعی** صفحه INDEX را نشان می‌دهد:

| کلید | متن روی نمایشگر | نتیجه |
| --- | --- | --- |
| 1L | `<IDENT` | IDENT |
| 2L | `<POS` | POS INIT |
| 3L | `<PERF` | PERF INIT |
| 4L | `<TAKEOFF` | TAKEOFF REF |
| 5L | `<APPROACH` | APPROACH REF |
| 1R | `NAV DATA>` | REF NAV DATA |
| 6R | `MAINT>` | Maintenance روی زمین |

مقدار **6L OFFSET** در متن صفحهٔ 11.40.7 شرح داده شده، **ولی در شکل 11.40.6 خالی است**؛ برای همین به‌صورت گزینهٔ وابسته به Effectivity ثبت شده و به‌زور وارد صفحهٔ تصویری نشده است.

## 11.40.7 — تفسیر کلیدها و شرایط

- 3L به PERF INIT برای VNAV و پیش‌بینی Performance می‌رود.
- 4L به TAKEOFF REF و ورودی اطلاعات برخاست و **V-speeds** می‌رود.
- 5L به APPROACH REF برای **VREF** اپروچ می‌رود.
- 6L (در صورت وجود گزینه) به **LATERAL OFFSET** می‌رود.
- 1R اطلاعات Navaid/Waypoint/Airport/Runway را در REF NAV DATA نشان می‌دهد. روی زمین اگر قبل از 1R رشتهٔ `SUPP` در Scratchpad باشد، **SUPP NAV DATA** باز می‌شود.
- 6R MAINT فقط روی زمین است؛ در پرواز پرامپت به **NAV STATUS** تبدیل می‌شود و وضعیت Navaidهای تنظیم‌شده توسط FMC را نمایش می‌دهد.
- 2L علاوه بر باز کردن POS INIT، برای ورود/به‌روزرسانی Magnetic Heading هنگام IRS در حالت ATT استفاده می‌شود.

## 11.40.8 — IDENT: شکل و اطلاعات اصلی

در شکل `IDENT 1/X` آمده و **X مقدار ثابت اثبات‌شده‌ای نیست**. داده‌های بیشتر این صفحه برای تأیید خلبان است؛ بخش‌های مربوط به دیتابیس فعال و دیتابیس تکمیلی امکان ورود دستی دارند.

| LSK | برچسب | منبع یا رفتار |
| --- | --- | --- |
| 1L | `MODEL` | مدل هواپیما از Performance Database |
| 2L | `NAV DATA` | شناسهٔ دیتابیس ناوبری |
| 4L | `OP PROGRAM` | شماره قطعهٔ نرم‌افزار Boeing و نسخهٔ FMC |
| 6L | `INDEX` | INIT/REF INDEX |
| 1R | `ENG RATING` | ریتینگ تراست از Performance Database |
| 2R | `ACTIVE` | بازهٔ اعتبار دیتابیس فعال |
| 3R | Inactive range | بازهٔ دیتابیس غیرفعال |
| 5R | `SUPP DATA` | تاریخ دیتابیس تکمیلی یا خالی |
| 6R | `POS INIT` | صفحهٔ بعدی Preflight |

نمایش نمونهٔ `737-XXX`، `XXX`، تاریخ‌های ۱۹۹۷ و `UXX.X` از **طرح آموزشی FCOM** آمده و نباید در نرم‌افزار ثابت شود. در پیکربندی EP-FSI این پروژه، ریتینگ موتور طبق تصمیم پیشین کاربر **20K** است؛ این تصمیم از نمونهٔ تصویری مستقل است.

نمونه‌های OP PROGRAM در متن به Updates `U5`، `U10.5A`، `U10.7` و `U10.8A` اشاره دارند، ولی این تصاویر نسخهٔ نصب‌شدهٔ EP-FSI را تعیین نمی‌کنند.

## 11.40.9 — انتخاب چرخهٔ ناوبری

FMC بازهٔ تاریخ **ACTIVE** و بازهٔ دیتابیس غیرفعال را جداگانه نشان می‌دهد؛ عنوان ACTIVE فقط بالای تاریخِ فعال ظاهر می‌شود.

**انتخاب چرخه:** خلبان تاریخ/بازهٔ موردنظر را با LSK مربوط به Scratchpad منتقل کرده، سپس آن را به خط ACTIVE منتقل می‌کند. تاریخ فعال قبلی به تاریخ غیرفعال منتقل می‌شود.

**گارد سخت:** دیتابیس فقط **روی زمین** تغییر می‌کند و تغییر آن، تمام داده‌های مسیر قبلی را حذف می‌کند. اگر دیتابیس هنگام پرواز منقضی شود، همان دیتابیس تا پایان پرواز و تغییر پس از فرود استفاده می‌شود. Supplemental Data در نبود دیتابیس تکمیلی، تاریخ خالی نمایش می‌دهد.

## مقایسه با کد جاری و مرزبندی

این اسناد روشن می‌کنند که INDEX جاریِ نمونهٔ `engine/ch11/physical-cdu/app.js` هنوز به FCOM وفادار نیست: نمایش موقت RTE/LEGS و بعضی برچسب‌ها در جایگاه‌های متفاوت است. IDENT نیز فعلاً فیلدهای ACTIVE/INACTIVE/SUPP DATA را ندارد و مدل را از مقدار نمایشی ثابت می‌گیرد. **هیچ تغییر اجرایی یا جابه‌جایی روی CDU فیزیکی در این Commit انجام نشده است**؛ تنها قرارداد صفحه‌به‌صفحه تهیه شد تا تغییرات بعدی دقیقاً از روی FCOM اعمال شود.
