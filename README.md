# ATA24 guest electrical test bench

This is a **separate standalone web application** for one invited account. It includes a local copy of the B737 Classic ATA24 bus/consumer training view and its dependencies, no cockpit link, no cross-tab storage transport, and no shared app APIs.

## Access policy

- Account: \`Ali.m\` (case-sensitive).
- Password: supplied to the owner separately; the server contains a *salted scrypt verifier*, not the plain password.
- Only **3 active browser devices** at the same time. Device identity is a random HTTP-only browser cookie, not a hardware fingerprint.
- A device slot stays active while its tab polls the protected /api/pulse endpoint, and expires after **20 minutes without requests**.
- PostgreSQL holds the session records across process restarts. Logins acquire a transaction-level advisory lock so parallel logins cannot bypass the 3-device cap.
- Logout immediately releases a slot. Separate browsers/profiles on the same physical computer count as separate sessions.
- Every HTML, JS, CSS and consumer-data request is authenticated **server-side**.
- Serving on a dedicated domain avoids any site-to-site links. The public URL must be generated by Railway, not the original site's Pages URL.

## Railway deployment

1. Deploy this branch as a **new Railway service** with its own Railway-generated domain and no existing service routing.
2. Provision a Railway PostgreSQL database in the same project.
3. Set \`DATABASE_URL=\${{Postgres.DATABASE_URL}}\` on the web service (use the actual service's reference name).
4. Run the app with its supplied Dockerfile. Railway sets \`PORT\`; no other secret is required for this preconfigured owner account.
5. Generate the public HTTPS domain for the guest service. Do not set up a redirect to another cockpit site.
6. Confirm the login gate, sign out, three simultaneous browsers accepted, and fourth rejected. Check that the guest site network panel only loads assets from its own domain.

## Source protection and caveats

The user-facing web app does not reference or request any other website. **This branch exists in the same GitHub repository as the original code**, so metadata in the public source repository is not private. For strong project provenance isolation, copy the standalone branch contents into a separate **private** repository before connecting Railway and disable source repository disclosure in deployments.

This is a training/education tool, **not** a flight-operations reference or certified electrical wiring diagram. A browser-only implementation cannot reliably identify an actual physical device, so the hard cap applies to server-tracked browser identities, with session inactivity expiry.
